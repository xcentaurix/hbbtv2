User's goal (decided 2026-09-19): an HbbTV **2.0** stack on OpenViX for Broadcom Dreamboxes (dm9xx). Not just fixing the existing 1.x plugin.

Route chosen: WPE WebKit (Igalia meta-webkit) + Open Red Button (github.com/OpenRedButtonProject/orb, Apache-2.0, main = HbbTV 2.0.5) with an enigma2 implementation of `ORBPlatform` (~55 pure-virtuals in rdk/ORB/library/src/platform/ORBPlatform.h, loaded via dlopen of /usr/lib/libORBPlatformImpl.so).

Findings that drive the plan:
- dm900/dm920 = BCM7252S, kernel 3.14, vendor EGL `libvc5dream` (native-pixmap fb surfaces via gEGLDC), no wayland/DRM/GBM. `meta-dream` has no WPE/HbbTV/Qt recipes; dm900 MACHINE_FEATURES has no hbbtv flag.
- OpenViX tree is OE `wrynose`, meta-qt5.15 present, no meta-webkit/WPE/Thunder.
- Existing oe-alliance plugin (`hbbtv-browser-webkit`) = ~2011 GTK WebKit fork (DirectFB, --disable-video/svg/jit) + closed `libhbbtvplugin.so`: dead end for 2.0, but its Python glue (aitreader/vbcfg/vbipc/plugin.py) is a blueprint for the enigma2-side integration (AIT, video window via /proc/stb/vmpeg, osd/rc lock).
- meta-webkit wpewebkit has PACKAGECONFIG `wpe-platform-headless`; WPE Platform API (2.50+) exposes WPEBuffer with `wpe_buffer_import_to_pixels()` (SHM path). It DEPENDS on virtual/egl + libgles2, so WebProcess GL on libvc5dream is the crux.
- ORB app manager/network services are platform-agnostic C++14 (libxml2 only) but its CMake find_package(WPEFramework) (Thunder) - needs decoupling.

**Why:** WPE avoids Qt WebEngine's eglfs/Chromium problems on this stack; rendering to buffers and compositing in enigma2's own GL layer sidesteps the vendor-EGL/no-Wayland issue.

**How to apply:** Go/no-go gates in order: (1) WPE builds for dm900 and renders a page to a buffer; (2) enigma2 shows that buffer as a texture, measure CPU/RAM at 720p (DM900 has 2GB RAM per user; dual-core Cortex-A15, fb 1920x3240 32bpp = 3 pages); (3) ORB core builds against its mock platform; (4) write enigma2 ORBPlatform impl (Broadcast group first). Unverified: meta-webkit support for wrynose, whether the WebProcess can create a usable GLES context on libvc5dream.
